# CodingChatRoom 多工作任务并行改造需求

## 1. 文档定位

- 项目：`CodingChatRoom.AvaloniaShell`。
- 本轮范围：探索当前实现，形成需求与设计，不实施业务代码改造。
- 配套文档：[多工作任务并行改造设计](CodingChatRoom-多工作任务并行改造设计.md)。
- 本文中“明确需求”来自本轮用户描述；“建议”用于补齐可实施的交互规则，未经确认不能当作既定产品决策。

## 2. 背景与目标

上一轮调整后，历史会话已成为独立页面，左侧没有常驻边栏。目前应用只组合了一套聊天运行对象。此次希望利用左侧区域承载多个独立工作任务项，在同一应用中并行开展编码工作，而不是只增加多个聊天入口、执行时仍全局排队。

核心目标：

1. 左侧展示工作任务列表，可新建、命名、删除任务项。
2. 每个任务有独立工作路径、模型选项及聊天执行上下文。
3. 多个任务能够同时工作，切换可见任务不影响后台执行。
4. 任务项内支持保留路径新建会话，以及按当前路径查历史。
5. 左侧仍有不带过滤的全局历史入口。
6. 工作任务与会话生命周期独立，任务状态可直接观察。

## 3. 概念与边界

| 概念 | 定义 | 与其他概念的关系 |
| --- | --- | --- |
| 工作任务项 | 用户组织并行工作的具名容器，不等于一次模型请求，也不等于历史会话 | 拥有独立配置、运行上下文，当前挂载至多一个会话（建议） |
| 会话 | 可持久化、可恢复的消息与 Agent 上下文 | 可以先后在不同任务中打开，不永久属于某个任务 |
| 一次执行 | 从发送请求开始，到流式输出、工具调用及收尾结束的操作 | 属于确定的任务和会话 |
| 活跃任务 | 右侧当前展示或作为导航上下文的任务 | 活跃不等于正在运行；后台任务也可以工作 |
| 全局历史 | 所有任务使用的会话索引与管理页面 | 不随任务删除而删除 |
| 工作路径 | 任务下一次执行所使用的代码目录 | 不作为任务 ID，也不意味着目录独占 |

建议使用独立的 `WorkTaskId` 与现有 `SessionId`。一个任务可以先后使用多个会话，但不需要建立永久“任务拥有的历史列表”。任务内历史入口按路径搜索，不按任务 ID 隐藏其他会话。

## 4. 明确功能需求

### FR-01 左侧任务列表

- 恢复左侧常驻区域，主要内容是纵向排列的工作任务项，而非历史会话列表。
- 提供“新建工作任务”按钮。
- 点击任务展示它的聊天内容、工作路径和模型选项。
- 每项可独立命名、独立删除，名称与会话标题互不联动。

### FR-02 任务独立与并发

- 不同任务的工作路径、模型选择互不覆盖。
- 任务 A 运行时，任务 B 可发送请求并进入工作状态。
- 切换任务、打开历史页面或设置页面不停止后台任务。
- 停止一个任务不能取消其他任务。
- 输出、工具调用、附件和错误必须归属原任务，不能因切换界面写入当前可见会话。

### FR-03 任务内新建会话

- 每个任务项提供“新建会话”。
- 新建的是会话，不是工作任务项。
- 保留任务的工作路径。
- 原会话仍可从历史入口查看，不因新建而删除。
- 建议同时保留模型、思考强度、自动压缩等任务配置，清空新会话的输入草稿与待发送附件。

### FR-04 任务内查看历史

- 点击任务项内“历史会话”后，打开历史页面。
- 搜索框自动填入该任务当前生效的工作路径，不使用未应用的路径输入。
- 每次进入都替换旧搜索条件；用户可以修改或清空。
- 这是可编辑搜索，不是不可移除的隐藏限制。
- 建议未设置路径时填入空字符串，显示全部会话并说明未设置路径。

### FR-05 全局历史入口

- 左侧保留独立“全部历史会话”入口。
- 每次进入显式清空搜索框及任何路径过滤状态，不能沿用上次任务内的搜索条件。
- 历史页面保持统一，避免为每个任务复制一套历史数据。
- 从全局历史选择会话的目标任务尚未确定，见第 6 节建议。

### FR-06 生命周期独立

- 删除工作任务不删除历史会话、会话日志、工作目录或代码文件。
- 重命名任务不修改会话标题；重命名会话不修改任务名。
- 历史会话删除仍是独立、显式操作，不应顺带删除任务。

### FR-07 状态展示

- 聊天正在执行时，任务项显示“工作中”。
- 正常完成后显示“空闲”。
- 非活跃任务也必须持续更新状态。
- 建议使用文字与视觉标记共同表示状态，不能只依赖颜色。

## 5. 建议的界面与操作规则

### 5.1 布局

左侧由“新建工作任务”、可滚动任务列表、“全部历史会话”和设置入口组成；右侧在当前任务聊天、历史页面、设置页面之间导航。任务项至少显示名称、工作状态，并提供新建会话、查历史、重命名、删除操作。路径和模型可以作为次级信息或悬浮提示，完整编辑区复用现有聊天区域。

建议在历史与设置页仍保留任务边栏，使用户可观察所有任务状态并快速返回聊天。点击某任务内的动作应以该任务为对象，不得误操作之前活跃的任务。

### 5.2 操作可用性建议

| 操作 | 空闲任务 | 工作中的任务 |
| --- | --- | --- |
| 切换展示、查看历史、重命名任务 | 允许 | 允许 |
| 发送消息 | 启动一次执行 | 保留现有消息注入语义，不启动第二条同任务执行链 |
| 新建或替换当前会话 | 允许 | 禁止并说明原因，其他空闲任务仍可操作 |
| 修改生效路径、模型、思考强度 | 允许 | 首期建议禁用；运行使用固定快照 |
| 停止 | 不适用 | 仅停止该任务完整执行链 |
| 删除任务 | 确认后删除容器 | 确认“停止并删除”，等待停止和保存完成后再删除 |

“工作中”应覆盖工具调用、手动/自动压缩、循环迭代等待和最终保存。可以提供“正在停止”“正在保存”等辅助说明；出现错误后显示空闲并保留失败提示，不能把失败伪装成成功完成。

## 6. 历史会话打开规则：建议方案，待确认

推荐“入口确定目标任务 + 已挂载会话优先定位”，避免正在工作的任务被替换。

1. 从任务项进入历史：进入时记录该任务 ID，页面显示“打开到：任务名称”。后续异步操作始终使用这个目标，不临时读取可变的活跃任务。
2. 从全局历史进入：以进入页面时的活跃任务为默认目标，搜索始终为空；允许显式改为“在新任务中打开”。
3. 会话已在任意任务挂载：直接定位已有任务，不创建第二个可写副本，不隐式抢占或迁移。
4. 会话未挂载且目标任务空闲：替换目标任务的当前会话，原会话仍保留在历史中。
5. 目标任务正在工作：禁止替换，提示可定位其他任务或在新任务中打开，不自动停止。
6. 没有目标任务或目标已删除：要求选择有效任务或新建任务，不静默替换其他任务。
7. 历史会话路径不同于目标任务：提示差异并确认切换到历史路径；取消或恢复失败时保留原任务状态。建议不要默认用新目录继续旧 Agent 上下文。
8. 路径不存在：允许查看历史，但禁止执行，直到用户选择有效路径并明确确认继续。
9. 历史不强制覆盖任务模型选项。模型已移除或不兼容时明确提示选择，不能静默换模型执行。

方案取舍：始终新建任务更简单但容易堆积任务；每次弹出目标选择更明确但打断操作。本建议兼顾快速恢复和并发安全，仍需产品确认。

## 7. 持久化与安全建议

- 建议保存任务 ID、名称、排序、路径、模型引用、运行选项、当前会话引用及活跃任务 ID，重启恢复任务列表。
- 会话继续使用现有会话存储，不复制到任务专属历史目录。
- 重启不自动重新执行模型请求或工具；上次未完成任务显示“上次执行中断”提示。
- 引用的会话已删除时保留任务配置并创建空会话，告知用户。
- 任务配置不保存 API Key；引用现有模型配置。
- 同目录任务并行存在修改同一文件、构建输出冲突等风险。首期建议提示风险，建议使用独立目录或 Git worktree，不宣称实现了文件系统隔离。
- 退出应用时列出正在工作的任务，允许返回应用或停止全部后退出；保存失败必须可见。

## 8. 非目标

首期不包含多 Agent 自动协作、任务依赖图、自动任务调度、多窗口、多用户远程管理、崩溃后自动续跑、自动创建 worktree、跨进程隔离或自动解决代码冲突。单个任务仍沿用现有单执行链及运行中消息注入能力。

任务数量与并发上限、精确路径过滤、草稿跨重启恢复等未在原需求中指定，不隐式加入强制承诺。

## 9. 验收场景

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| AC-01 | 创建 A、B，分别配置不同目录和模型 | 来回切换后配置不串扰 |
| AC-02 | A 未完成时启动 B | 两条执行链均已启动且尚未完成，不是串行伪并发 |
| AC-03 | A、B 流式执行时反复切换界面 | 消息、工具结果、异常各回到原会话 |
| AC-04 | 停止 A | B 继续运行，A 收尾完成后空闲 |
| AC-05 | 在 A 内新建会话 | A 的路径保留，任务 ID 不变，旧会话可查 |
| AC-06 | 从 A 内查历史，再从全局入口查历史 | 前者搜索为 A 路径，后者搜索为空且无隐藏过滤 |
| AC-07 | 重命名/删除 A | 会话标题、历史记录及工作文件不受影响 |
| AC-08 | A 完成，当前显示 B | A 状态更新为空闲 |
| AC-09 | 打开已由 A 挂载的会话 | 按建议定位 A，不产生并行写同一会话 |
| AC-10 | 历史加载失败或取消跨路径确认 | 原任务路径、模型、会话不变 |
| AC-11 | 循环任务进入等待或自动压缩 | 保持工作中，停止不会自动进入下一轮 |
| AC-12 | 删除运行任务或退出应用 | 按确认流程停止、等待、保存、释放；失败可见 |
| AC-13 | 重启应用 | 按持久化建议恢复任务，不自动执行旧任务 |
| AC-14 | A 保存的会话在全局历史查看 | 无需重启即可看到更新；B 运行不阻塞浏览 |

其中 AC-09 至 AC-13 涉及建议方案，在方案确认后作为正式验收要求。

## 10. 待确认清单

| 问题 | 推荐选项 |
| --- | --- |
| 全局历史恢复到哪里？ | 默认进入时的活跃任务，提供新任务打开 |
| 同一会话能否同时挂载多个任务？ | 首期单一可写挂载，重复打开定位已有任务 |
| 跨路径历史如何恢复？ | 确认采用历史路径；不默认沿用目标任务路径 |
| 工作中能否替换会话？ | 禁止；使用另一个任务 |
| 运行任务如何删除？ | 确认停止并删除，等待收尾，保留会话 |
| 任务列表是否跨重启保存？ | 保存配置和会话引用，不自动续跑 |
| 同目录并行是否禁止？ | 首期风险提示，不保证文件隔离 |
| 路径搜索是否必须精确匹配？ | 首期复用现有标题/路径包含搜索，明确非精确过滤 |
| 初次启动与删完最后一项如何处理？ | 初次创建默认任务；删完展示新建任务空态 |
| 是否限制并发数？ | 首期先验证至少双任务并发，再依据资源测试决定上限 |

## 11. 当前实现的约束摘要

当前界面已具备独立历史页面与路径搜索基础，但历史 ViewModel 绑定单个应用实例；聊天模型选择会修改端点管理器的 `PrimaryModel`；运行实例与 CodingAgent 缓存也都是单份。不能只添加左侧列表或共享一套 ChatViewModel 来达成上述需求。具体证据、隔离边界及实施顺序见配套设计文档。
